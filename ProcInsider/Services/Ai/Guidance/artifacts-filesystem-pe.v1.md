# Artifacts, filesystem and PE
File artifacts, filesystem metadata and PE analyses describe stored observations at their acquisition/analysis time. Retain exact paths, hashes, source runs, analyzer versions and timestamps with their meaning. File existence in a snapshot is not proof of execution; an executable header, import or string is not proof that code ran. Signature status concerns the checked file/version and verification conditions, not universal trust.
GetForensicEvidence, when offered, pages stored forensic results. input_sha256 selects an exact 64-hex input hash; source_path_exact selects the exact case-sensitive recorded path spelling. Combined selectors use AND within the admitted scope before counts/paging. They read stored metadata, never arbitrary files. GetForensicProperties pages native fields of one checked result, retaining value types/nulls and explicit whole-field omissions; omitted oversized fields remain uninspected. Both Tools disclose offset bounds; a continuation beyond the bound remains explicitly unavailable. Read occurrence history is not included.
Inspect only stored records available through suitable offered Tools. A path in a process or event is a reference, not authority to open an arbitrary file. No shell, arbitrary filesystem or URL access is implied by this guide. Missing analysis or unavailable originals must be stated as coverage gaps.
