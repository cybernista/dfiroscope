# Process inventory and tree
Recorded process metadata describes observed executable paths, command lines, users and lifetimes. It does not prove all executions or the intent of an executable. Explain known executable purpose separately from the checked capture. Parent/child claims require qualified relation evidence; a PID reused across lifetimes must not join unrelated records.
When GetHostProcesses is offered, omit time bounds for an explicit inventory total within the checked source/execution-root boundary. process_name_contains matches recorded names; offset pages matching rows. A bounded initial page is a preview. total_count precedes requested name/time filtering; matching_count reflects those filters. Use the supplied exact Tool schema. Aggregate counts may cite checked coverage without inventing process references. GetProcessDetails and tree/event/network pivots use exact checked reference_id only when offered; the conversation target remains pinned.
SearchSnapshotProcesses/CountSnapshotProcesses, when offered, support exact process_id and process_entity_id selectors within the admitted boundary. A PID filter may match reused lifetimes; it is not durable identity. The query must return fresh checked references before any exact-object pivot; an entity ID supplied in a question or old turn is a selector, never current checked reference authority. Immutable process-observation pages retain their exact run provenance and omitted payload/field-map/metadata coverage.
